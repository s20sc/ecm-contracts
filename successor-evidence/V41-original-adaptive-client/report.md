all objects belonged to the selected provider. All557 source/runtime inputs and
1509 metadata candidates matched; the latter inventory exactly matches all six
sealed V39 workflow observations. No entry-point plugin, ROS, network or install
was invoked. No warnings were captured in these three discovery observations.

observation only; it does not validate nonempty ROS extension discovery.

was not counted. Complete unchanged client source supports the adaptive branch;
there is no independent branch-line instrumentation.

client preserves output on the same3.12 API on which original rosidl fails at
get. This is an observed same-API consumer difference and another scoped false
alarm: the name-reference rule does not encode adaptive behavior. It does not
supply primary consumer-condition benefit, general specificity/accuracy,
prospective samples, original deployments, independent human labels, or new
primary/control labels. No prior failures were rerun or rewritten.

retained provider modules, with a process-local binding/discovery bridge. Original
provider and client implementations are unchanged; host substitution remains a
limitation. Exact receipts and compact hashes are in receipt.json; raw data
remain in the external directory rather than being duplicated as a dataset.
